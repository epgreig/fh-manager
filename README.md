# fh-manager

Fantasy hockey draft board generated by a spreadsheet-bound Google Apps Script. Three side-by-side groups: Forwards, Defensemen, Goalies. Draft and undo macros maintain a pick log. This initial version is a local code deliverable; it has not yet been installed or tested in a live Google Sheet.

## Set up

1. Install Python dependencies: `python3 -m pip install -r requirements.txt`.
2. Run `python3 scripts/import_athletic.py ~/Downloads/2026-27-Fantasy-Projections-Yahoo.xlsx`.
3. Create an empty Google Sheet. Open **Extensions > Apps Script** and add `Engine.gs`, `Code.gs`, `Names.gs`, `Pan.gs`, and the locally generated `ProjectionData.gs` from `apps-script/`.
4. In project settings, enable the manifest editor and replace `appsscript.json` with this repository's manifest.
5. Run `setupDraftSheet`, authorize access to this spreadsheet, and reload the sheet. Setup preserves existing input tabs; refreshing rebuilds only Board.
6. Enter keepers in **Keepers**, using player names from **Players**, each team's draft slot, and cost round. Complete this before logging picks.
7. Populate **ESPN POS**, **ESPN ADP**, and source/date in **Players** from ESPN. Then use **Draft > Refresh board**.
8. Select any visible cell belonging to a player on Board and invoke **Draft selected player**. Use **Undo last pick** for a mistake. Configure shortcuts 1 and 2 in **Extensions > Macros > Manage macros**; use the key combination shown by Sheets on your Mac.

## Scoring

Skaters: `3 G + 1.5 A + 0.3 BLK + 0.5 PIM + 1.5 SHP`.
Defensemen receive another `0.3 × (G + A)`.
Goalies: `1.5 W + 2 SO − GA + 0.2 SV`.
All values are editable in Settings. Refresh after changing inputs. The Athletic's fantasy scores, keeper flags, Yahoo eligibility, and Yahoo/Fantrax ADP are not substituted for league settings or ESPN data.

## League and values

12 teams, snake draft, editable slot (default 1), 16 rounds including keeper selections. Rosters: 2 C, 2 LW, 2 RW, 3 D, 1 skater FLEX, 1 G, 5 bench, 1 IR. IR does not add a draft round. Each team can have up to 2 keepers costing distinct round picks. Teams are identified by initial draft slot. Traded picks and overlapping keeper round costs need an explicit pick ownership table in a later iteration.

**PAR** is season points minus the fantasy points of the player at the configured replacement rank for C, LW, RW, D, or G. Settings contains ranks, not point values: `replacementC` (49), `replacementLW` (37), `replacementRW` (37), `replacementD` (49), and `replacementG` (25). Defaults approximate 4 C / 3 LW / 3 RW / 4 D / 2 G rostered per team, including flex and bench. Adjust these assumptions for your league. Rank 49 means the 49th-highest projected player eligible at that position.

Forwards stay in one board panel. A multi-position player appears in each eligible replacement pool and receives their highest eligible PAR (the lowest replacement baseline). This is a scarcity approximation, not a unique-player roster assignment optimizer. Baselines include keepers and drafted players, so they remain fixed during the draft. ESPN POS is preferred. When blank, the Athletic workbook positions are used provisionally and marked with an asterisk on Board; these are not verified ESPN eligibility. Unknown positions or a pool smaller than its configured rank leave affected PAR blank. Refresh automatically replaces the legacy replacementF setting with the three new defaults, preserving any existing C/LW/RW ranks and D/G settings.

Purple marks the top approximately 15% of available PAR values across all groups. Blue marks the lowest approximately 10% of positive available ESPN ADPs across all groups. Separate metric cells allow both colors to appear for one player. Ties can expand the highlighted fraction.

**PAN (points above next)** estimates the cost of passing: `P(gone before next pick) × (positional PAR − expected best alternative PAR)`. It uses ESPN ADP and a normal distribution with positive `adpSigma` (default 12 picks), conditional on the player still being available at the current pick. The horizon is the actual count of intervening non-keeper selections, so consecutive picks give zero PAN. No subsequent own pick gives blank PAN.

Separate C/LW/RW/D/G pools estimate the best alternative using each player's survival probability and the probability every better option is gone. The candidate is excluded from their own fallback. Drafted and kept players have zero availability. The reserve fallback is zero PAR if all alternatives disappear; negative-PAR alternatives cannot lower it. Multi-position players receive the maximum positional PAN among eligible pools. This measures positional urgency, not a complete roster optimizer.

PAN uses ordinary spreadsheet formulas in Board Data and the hidden PAN Pools tab; there is no simulation or PAN custom-function runtime. Unknown ADP in a relevant pool leaves its PAN blank. The model assumes independent player availability, ignores opponent roster needs, and uses an assumed rather than fitted ADP uncertainty. Formula inputs follow Draft Log edits immediately. Refresh after projection/scoring/eligibility/replacement-rank edits.

## Data and additional sources

The importer reads cached **The List** season totals, including the source's player adjustments, rather than multiplying the raw per-game **Player Data**. Missing scored stats fail loudly. The raw workbook, extracted data, and generated `ProjectionData.gs` are versioned in this public repository at the repository owner's request. Source data remains attributed to The Athletic; this repository does not grant a license to third-party data.

The Projections table supports additional sources using the same player ID and season-total stat columns, with nonnegative weights. Each stat is blended using only sources that supply that stat; missing stats do not become zero. Rankings alone cannot be blended into projected stats. Do not add the same source/player twice.

ESPN eligibility is platform-specific: use ESPN's player list or your league's draft room. ESPN can grant additional eligibility; Yahoo POS is retained solely as a reference column. An automated ESPN importer is not included yet because current-season endpoint access and field coverage have not been verified. No ADP or eligibility is fabricated.

FantasyPros offers hockey consensus rankings, but its support documentation says NHL Draft Wizard/My Playbook tools are unavailable. Confirm a downloadable statistical projection source before assigning it a projection weight.

## Updating an existing sheet

Code updates use Google's clasp tool, the same approach as ff-manager. This project is connected locally to the hockey sheet's bound script. No separate Google Cloud project or self-updater is needed.

After code changes, run tests from the repository root, then run `clasp push` from `apps-script/`. Reload the spreadsheet and choose **Draft > Refresh board** to apply the latest layout. Pushing code does not change worksheet data. The refresh preserves settings, projections, keepers, targets, and the draft log.

For a fresh connection: install `@google/clasp`, run `clasp login`, enable the Apps Script API in https://script.google.com/home/usersettings, and create an ignored `apps-script/.clasp.json` containing `{"scriptId":"YOUR_SCRIPT_ID","rootDir":"."}`. Do not clone over the repository's source files. Back up existing remote code in a separate directory before the first push.

The former self-updater has been removed, along with its external-request and script-project permissions. The sheet itself requests access only to its current spreadsheet. Google authorization for clasp is handled separately on the developer's computer.

## Compact layout and name lists

The board uses approximately 1,030 visible pixels at 100% zoom, plus row headers and browser chrome. Use Sheets zoom below 100% on smaller windows. Forwards show Player/POS/Tm/PAR/ADP/PAN; D and G omit POS. Points and internal IDs remain hidden for compatibility. Purple marks top PAR values; blue marks low ADP values. Displayed numbers round to whole values while calculations keep full precision.

Type player names in **Targets** column A or **Fades** column B of the Targets sheet. Names are highlighted pale orange or pale grey on Board immediately after edits. Fade takes precedence if a player appears in both lists. Both columns have name dropdowns and adjacent match-status columns; invalid names turn red. Capitalization and surrounding spaces are normalized, but spelling must match Players. Removing a name clears its highlight.

Keepers also accepts names with a dropdown and a Name check column. Old keeper IDs convert automatically on refresh. Invalid or ambiguous keeper names block refreshing/drafting until corrected. After editing keeper names or costs, use **Draft > Refresh board**; the name-check status updates immediately while typing. All other keeper constraints still apply.

PAR does not depend on pick spacing. PAN recalculates after each pick using the next own pick and the intervening non-keeper selections. For slot 1: pick 1 looks toward pick 24 (22 intervening selections); pick 24 looks toward pick 25 (zero); pick 25 looks toward pick 48. Consecutive picks still compare against remaining alternatives excluding the player taken now. One dynamic PAN column covers both short and long waits.

Project content updates: https://developers.google.com/apps-script/api/reference/rest/v1/projects/updateContent

Draft and undo now update board values and conditional formatting without rebuilding widths, borders, fonts, or row heights. Full layout work runs only on Refresh board. The header shows current and next own pick; the legend is removed. PAR uses a shared white-to-purple scale from the top-fraction cutoff to the highest available PAR across all groups. PAN recalculates through spreadsheet formulas; Google service latency remains.

## Live draft filtering

Board panels now use FILTER/SORT formulas, following ff-manager. Draft and undo only modify Draft Log. Clearing log entries immediately restores non-keeper players through spreadsheet recalculation, without a script refresh. Keep the header row; clear the data rows. The hidden Board Data tab holds calculated projections and live availability formulas. PAN recalculates through ordinary formulas independently of the player-list spill.

Row 2 contains group titles, row 3 headers, and players begin on row 4. There is no hidden spacer row. Name highlighting uses conditional formatting so it follows moving players. Refresh board after changing scoring, projection inputs, replacement ranks, or eligibility to rebuild calculated values. Draft Log, keeper exclusions, and Targets/Fades are live. PAN has no custom-function runtime limit; missing ADP in a relevant pool leaves PAN blank.

## ESPN ADP and eligibility

Use **Draft > Import ESPN snapshot** to fill ESPN POS and ADP in Players from the versioned public ESPN snapshot, then refresh the board automatically. This replaces matched ESPN fields, including manual edits, and records the source URL and retrieval time. ESPN Import reports each player's result. It imports a bundled dated snapshot, not a live request from Google Sheets, so no extra Google authorization is required.

The September 6, 2026 snapshot contains 1,686 ESPN players and matches all 670 Athletic players, including 19 reviewed spelling aliases resolved to ESPN IDs. Positional eligibility uses eligibleSlots (C=0, LW=1, RW=2, D=4, G=5); generic forward, utility, bench and IR slots are excluded. ADP is ownership.averageDraftPosition from ESPN drafts; it is not customized to this league's scoring or keepers. This public, undocumented ESPN endpoint may change.

To refresh the snapshot from ESPN, run `python3 scripts/fetch_espn.py --season 2027`, run tests, and push the scripts with clasp. Then use the sheet's Import ESPN snapshot menu. The importer fails if ADP is absent or the 2,000-player cap is reached; it does not silently publish partial pagination.

The Projections tab includes a Player name column at the right, looked up from its stable ID. Board panels display ADP to the left of PAR; sorting remains descending PAR.

ESPN source: https://lm-api-reads.fantasy.espn.com/apis/v3/games/fhl/seasons/2027/segments/0/leaguedefaults/1?view=kona_player_info

ADP uses a shared blue-to-white gradient across all three panels, from the lowest available ADP to the configured bottom percentile (default 10%); later ADPs stay white. PAR retains its top-15% white-to-purple gradient. PAN uses a white-to-orange gradient with a fixed minimum of zero; zero and negative PAN stay white.
